# 0.6.68 meeting-note reliability

## Regressions

`bash scripts/test-meeting-summary.sh` exercises production summary normalization, aggregation, source evidence, transcript segmentation, overlap removal, and saved-text restoration.

Observed red cases before their fixes:

- Valid semantic actions replaced with conversational keyword matches.
- Decimal versions split into multiple transcript entries.
- Filler differences prevented removal of matching cross-source echo.
- Short acknowledgments were treated as sufficient echo evidence.
- No review marker for material following a late exchange of farewells.

Passing checks include action lists longer than six, instruction-leak rejection, all 100 parts retained during aggregation, negation differences retained, post-meeting text preserved, existing timestamped formats restored, original transcript body preserved byte-for-byte when notes are refreshed, and evidence restricted to existing source entries.

## Full local evaluation

The user-authorized private meeting stays outside Git and Linear. No private fixture, summary, or recording is committed.

The full-meeting evaluation exposed a model guardrail error and a final context overflow in earlier candidates. Neither may be hidden by an opening-utterance fallback. The revised pipeline uses Apple's supported content-transformation model configuration, bounded per-part processing, separate structured follow-up extraction, and bounded overview synthesis. Key points and actions do not pass through an overflowing final condensation request.

An intermediate candidate completed but failed manual quality review: it promoted recommendations into tasks, omitted commitments, and reconstructed source quotations. It was not published. Task evidence now resolves to actual transcript entries, copied verbatim by application code rather than reconstructed by the model.

## Scope and limitations

This does not repair past ASR substitutions or restore words absent from the recording/transcript. Cross-source echo handling remains conservative and requires real audio evaluation for a measured accuracy claim. Farewell detection is explicitly a review hint, not an automatic trimming rule. Generated task interpretation, owners, and dates still require user review; source evidence is available to check them.

## Publication gate: not passed

Further Apple-model evaluation still promoted anecdotes and architectural descriptions into tasks and sometimes selected an irrelevant evidence entry. Source-entry existence is not proof that it supports the generated task. A local `gpt-oss:20b` whole-meeting benchmark produced a clearer overview but invented deadlines despite instructions not to do so (156 seconds; 21,342 prompt tokens; 992 output tokens; model unloaded afterward). Neither output is approved for release.

Signed/notarized candidate archives are internal QA artifacts only. They must not be described as a published or quality-verified release. The installed/public 0.6.67 remains unchanged pending a successful quality gate. The user's history was backed up before potential installed-app testing and has not been edited by this work.

Installed-app and final artifact results must be recorded after verification, not inferred from successful unit tests or notarization.
